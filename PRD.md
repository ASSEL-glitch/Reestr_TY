# PRD: Реестр ТУ на кабельную канализацию и ВЛС

**Версия:** 0.1 (черновик)
**Дата:** сентябрь 2026
**Статус:** MVP реализован (статическая веб-версия), документ описывает текущий охват и следующие шаги.

---

## 1. Контекст и проблема

Учёт технических условий (ТУ) на кабельную канализацию и воздушные линии связи (ВЛС) ведётся в Excel-файле (`.xls`) согласно приказу №189 от 20.06.2025. Реестр за 2026 год содержит 126 записей и продолжает пополняться.

Проблемы текущего процесса:
- Excel-файл неудобно просматривать и фильтровать на телефоне или при быстром поиске конкретной заявки.
- Нет единого представления «на каком этапе находится ТУ» без прокрутки по 14 столбцам.
- Файл живёт локально у одного человека — нет простого способа поделиться актуальным срезом с коллегами или руководством.
- Статус «Выполнено (Да/Нет)» заполняется вручную и не отражает реальный этап (ПИР → проект → СМР → акт).

## 2. Цель проекта

Дать сотрудникам, ведущим и проверяющим реестр ТУ, быстрый веб-доступ к данным: искать, фильтровать, видеть детали по каждой заявке — без открытия Excel и прокрутки в обе стороны.

**Метрики успеха (предлагаемые, требуют согласования с владельцем процесса):**
- Время нахождения конкретной заявки по номеру ТУ или населённому пункту — менее 10 секунд.
- Реестр открывается и читается на мобильном устройстве без горизонтальной прокрутки основных полей.
- Актуальность данных в веб-версии — не более 1 рабочего дня отставания от исходного файла.

## 3. Пользователи

| Роль | Потребность |
|---|---|
| Инженер/специалист, ведущий реестр | Быстро найти и обновить запись, проверить, что не выдано вовремя |
| Руководитель отдела | Обзор по кварталам/населённым пунктам, без деталей |
| Смежные службы (аренда, СМР, ПИР) | Проверить статус по конкретному ТУ, не запрашивая файл у ответственного |

## 4. Объём

### В рамках MVP (реализовано)
- Просмотр всех записей реестра 2026 года в табличном виде.
- Поиск по номеру ТУ, населённому пункту, примечаниям, датам.
- Фильтр по кварталу (I/II/III) и по населённому пункту.
- Сортировка по любому из основных столбцов.
- Разворачивание строки — доп. поля: ПИР, проект, СМР, акт, аренда, изменение, продление, примечание.
- Сводная панель: всего ТУ, число населённых пунктов, число записей с доп. сведениями, распределение по кварталам.
- Адаптивная вёрстка (десктоп/мобильный), автономный HTML-файл без серверной части.

### Вне рамок MVP (кандидаты для следующих версий)
- Редактирование данных в интерфейсе (сейчас источник истины — исходный Excel-файл).
- Хранение истории изменений / аудит.
- Многопользовательский доступ с ролями и правами.
- Загрузка вложений (скан акта, письма, проекта).
- Учёт нескольких лет в одном интерфейсе (сейчас — только лист «2026»).
- Уведомления о приближающихся или просроченных сроках выдачи ТУ.
- Реальный статус-воркфлоу вместо единственного поля «Выполнено (Да/Нет)».

## 5. Функциональные требования

### 5.1 Реестр (таблица)
- Отображать поля: № п/п, населённый пункт, дата заявки, № ТУ, дата выдачи, статус.
- Каждая строка кликабельна и разворачивает панель с дополнительными полями, если они заполнены; иначе — сообщение «дополнительных сведений нет».
- Строки с доп. сведениями визуально помечены (индикатор рядом с названием населённого пункта).

### 5.2 Поиск и фильтрация
- Текстовый поиск должен искать по: населённому пункту, номеру ТУ, примечанию, продлению, изменению, датам.
- Фильтр по кварталу — на основе даты заявки.
- Фильтр по населённому пункту — выпадающий список, построенный из уникальных значений данных.
- Фильтры и поиск комбинируются (логическое И).

### 5.3 Сортировка
- Клик по заголовку столбца переключает сортировку по возрастанию/убыванию.
- Даты сортируются как даты, а не как строки.

### 5.4 Сводка
- Общее количество записей, число уникальных населённых пунктов, число записей с доп. сведениями.
- Распределение по кварталам (числа и визуальные столбики).
- Счётчик «показано X из Y» обновляется при каждом фильтре/поиске.

## 6. Модель данных

Источник — лист «2026» файла `РЕЕСТР_ТУ_на_кабельную_канализацию_и_ВЛС.xls`. Поля на запись:

| Поле | Описание |
|---|---|
| `n` | Порядковый номер |
| `loc` | Населённый пункт / область |
| `order_date` | Дата поступления заказа на разработку ТУ |
| `tu_num` | Номер технических условий |
| `done` | Выполнено (Да/Нет) |
| `issue_date` | Дата выдачи ТУ |
| `pir` | Разрешение на ПИР |
| `project` | Согласованный проект |
| `smr` | Разрешение на СМР |
| `act` | Акт выполнения ТУ |
| `rent` | Договор на аренду |
| `change` | Изменение |
| `prolong` | Продление |
| `note` | Примечание |
| `order_quarter` | Квартал (вычисляется из даты заявки) |

## 7. Нефункциональные требования

- **Производительность:** мгновенный отклик поиска/фильтра/сортировки на 100–500 записей (без сервера, вся логика на клиенте).
- **Доступность:** видимый фокус для клавиатурной навигации, читаемый контраст текста.
- **Совместимость:** современные браузеры (Chrome, Safari, Edge), корректное отображение кириллицы.
- **Автономность:** файл должен открываться и работать без интернета и без сервера (кроме подключаемого веб-шрифта — с деградацией на системный шрифт при недоступности сети).

## 8. Текущее технологическое решение

- Статический HTML/CSS/JS-файл, данные встроены в разметку в виде JSON.
- Нет бэкенда и базы данных — обновление данных требует повторной генерации файла из Excel.
- Хостинг: файл передаётся получателю напрямую; постоянная публичная ссылка потребует размещения на стороннем хостинге (например, GitHub Pages, внутренний портал компании).

## 9. Риски и открытые вопросы

- **Актуальность данных.** Без интеграции с источником (Excel/1С/база) веб-версия быстро устаревает. Нужно решить: ручной re-export или автоматическая синхронизация.
- **Поле «Выполнено».** Во всех 126 текущих записях стоит «Нет» — статус, по факту, не отражает прогресс по этапам (ПИР/проект/СМР/акт). Нужно определить, что считается «выполнено», и в идеале — заменить на статус-воркфлоу.
- **Права доступа.** Публикация реестра как ссылки означает, что все, у кого есть ссылка, видят все записи, включая примечания. Нужно ли ограничивать доступ?
- **Много лет данных.** Текущий файл — только 2026 год; нужно решить, добавлять ли архив прошлых лет в тот же интерфейс.

## 10. Предлагаемый roadmap

| Этап | Содержание |
|---|---|
| **MVP (готово)** | Просмотр, поиск, фильтры, сортировка, детализация — статический файл |
| **V1** | Механизм регулярного обновления данных (скрипт пересборки из Excel по расписанию или по запросу) |
| **V2** | Учёт нескольких лет, экспорт отфильтрованной выборки обратно в Excel/PDF |
| **V3** | Редактирование в интерфейсе, статус-воркфлоу по этапам, история изменений, уведомления о сроках |
